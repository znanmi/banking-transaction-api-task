# Banking Transactions API

A RESTful banking API built with Java 21 and Spring Boot 4.1. It supports creating accounts, transferring funds between accounts, and retrieving an account's transaction history. Data is stored in memory.

> Status: in progress. This README describes the planned design and will be updated as features are completed.

## Tech stack

- Java 21
- Spring Boot 4.1 (Spring Web, Validation)
- Maven (via the included Maven wrapper)

## Build and run

Requires JDK 21. No other installs are needed; the Maven wrapper downloads Maven automatically.

```bash
./mvnw spring-boot:run   # start the app on http://localhost:8080
./mvnw test              # run the tests
```

## Planned endpoints

| Operation           | Method and path                              | Success     |
| ------------------- | -------------------------------------------- | ----------- |
| Create account      | `POST /accounts`                             | 201 Created |
| Transfer funds      | `POST /transfers`                            | 201 Created |
| Transaction history | `GET /accounts/{accountNumber}/transactions` | 200 OK      |
| View account        | `GET /accounts/{accountNumber}`              | 200 OK      |

## Business rules

| #   | Rule                                            | Enforced in                      |
| --- | ----------------------------------------------- | -------------------------------- |
| 1   | Amount is present and numeric                   | Controller (input validation)    |
| 2   | Amount is greater than zero                     | Controller, with a Service guard |
| 3   | Amount has at most 2 decimal places             | Controller                       |
| 4   | Initial balance is zero or more                 | Controller                       |
| 5   | Source and destination accounts are different   | Service                          |
| 6   | Source and destination accounts exist           | Service                          |
| 7   | Source account has sufficient funds             | Service                          |
| 8   | A transfer is all or nothing                    | Service                          |
| 9   | Concurrent transfers cannot overdraw an account | Service                          |

## Design decisions

- **Three layers, organized by layer:** Controller (HTTP and input validation), Service (business rules), Repository (storage). Each layer has its own package so the structure is visible at a glance.
- **Double-entry ledger:** each transfer creates a DEBIT entry on the source account and a CREDIT entry on the destination, linked by a shared transfer reference. Each entry records the balance after the transaction.
- **Opening deposit:** an account's initial balance is recorded as a CREDIT entry, so an account's entries always add up to its balance.
- **Two repositories:** accounts and ledger entries are stored separately, since accounts are updated and ledger entries are only ever added, never changed.

## Assumptions

- Single bank and single currency.
- Account numbers are generated by the server.
- Data is held in memory and is lost when the application stops.
